# Web 远程工作区体验改造

目标：让用户围绕“打开远程项目并持续工作”操作。对齐 VS Code Remote 的使用习惯，同时保留 DSH 的会话、工作区和工具模型。

本文记录体验目标和实施边界。现已在隔离的 DSH Web 0.2.0-rc.2 宿主中验证主要打开流程；下列性能目标仍需真实网络环境测量。

## 当前基础与主要阻力

已有 SSH config 主机发现、搜索与分组、最近目录、会话绑定、镜像同步、目录缓存、远程终端和文件栏。应复用这些能力。

| 改造前观察（历史基线） | 当时的代码依据 | 使用上的影响 |
| --- | --- | --- |
| 主机连接入口在设置页；设置组件也管理转发、审计、更新、清理和凭据表单 | `lib/client.js: RemoteWorkspacePage` | 高频的打开项目操作与低频管理操作混在一起 |
| 设置页连接后再弹目录选择；通用工作区选择器又维护另一套主机/路径状态 | `connectHost`、`DirPicker` | 相同任务有多条操作路径，需要统一语义和反馈 |
| 补全原先 Enter 总选第一项，目录及主机弹出项主要依赖鼠标 | `DirPicker` | 不能像熟悉的开发工具一样连续键盘操作；本轮先修路径补全 |
| 连接展示包含行级探测结果、全局 currentId 和会话镜像标识 | `rowState`、`refresh`、`useSessionMirror` | “选中过”“探测成功”“此会话已连接”需要明确区分 |
| 多处请求仍通过共享 current 选择目标，已有身份重申与回显保护 | `ensureCurrent`、`fetchDirList`、`commitPath` | UI 整合时必须保留多会话隔离，不能用一个全局“已连接”取代 |
| 文件栏已有失败时保留旧列表的 softError | `RemoteExplorerTab` | 恢复体验可在现有缓存上增强，避免断线时整棵树消失 |

## 目标流程

首次使用：打开远程项目 → 选择或添加 SSH 主机 → 认证/信任确认 → 选择目录 → 工作区打开。

日常使用：打开远程项目 → 搜索最近项目（主机名 + 目录名）→ 打开。连接建立和目录准备在同一个操作中完成。

持续工作：会话顶部清楚显示“主机 · 目录 · 连接状态”；文件栏和终端跟随该会话。网络断开后保留树、已打开文件和编辑草稿，提供重试。未经明确确认，不重放写入、删除、执行命令等操作。

## 分期实施与验收

### 1. 打开项目：统一入口、缩短重复操作

- 提供宿主支持的“打开远程项目”入口，保留原生 Add workspace 集成；先核实 slots/commands 契约，再决定入口位置及快捷键，避免覆盖宿主快捷键。
- 首屏以最近项目和可搜索主机为主；每行明确显示主机、目录和操作。主机管理与高级连接参数进入次级界面。
- 路径补全支持方向键、选中态、Enter、逐层 Escape、输入法和读屏语义。本轮已实现这一部分。
- 保留当前目录缓存、请求去重与过期响应保护；关闭/切换主机时不得让旧响应恢复旧列表。
- 验收：已保存项目无需先进入设置页；可全键盘选目录；一次用户确认只创建/打开一次工作区；取消后晚到响应不得继续打开项目。

### 2. 等待和失败：让每一步都可理解、可恢复

- 建立以操作和会话为单位的状态：未连接 → 连接中 → 认证/信任待处理 → 准备目录 → 就绪；另有失败、已取消、连接中断。
- 有后端事件证据才显示具体阶段。没有阶段事件时只显示“连接中”，不要伪造“正在认证”或百分比进度。
- 操作立即显示忙碌态并防重复提交；取消要传播到该操作的后端资源，不能仅关闭弹窗。不得取消其他会话共享的连接。
- 把认证失败、主机密钥变化、目录不存在、超时和连接中断分别映射到就地恢复动作，保留输入和原始诊断详情。
- 只对幂等读请求考虑有限重试。写入失败必须区分“未执行”和“结果未知”，不得静默重试。
- 验收：慢连接、拒绝认证、取消、断线均可恢复；本地会话不显示远程忙碌；A/B 两个远端同时打开时不会串机。

### 3. 持续工作：文件、终端、同步形成一个项目体验

- 文件树补齐统一的方向键导航、刷新、空态、加载态和右键菜单；弱网刷新保留旧内容并标识失效状态。
- 会话标题/状态入口提供重新连接、打开终端、切换远程项目等少量高频操作；转发、审计、清理放入管理入口。
- 将镜像同步的状态收敛为准备中、已同步、有本地改动、冲突、失败；冲突时清楚给出本地/远端版本及解决动作。
- 验收：断线和恢复保留展开目录、文件位置、编辑草稿；重连恢复读请求；同步冲突不会静默覆盖内容。

## 技术边界和验证方式

VS Code Remote 在远端运行开发服务；本插件目前结合远程 SSH/SFTP 和本地镜像。相似的 UI 不能自动保证语言服务、文件监控、任务、Git 和扩展都在远端执行。逐项明确这些能力的执行位置，另行评估是否需要远端服务，不能承诺换一个界面就获得完整 VS Code Remote 能力。

优先提取共享的连接/打开项目控制逻辑，逐步拆分 `client.js` 中的设置页、项目选择器和文件栏；避免在一次外观改造中重写连接池、镜像和路由协议。

每期验证真实客户端交互、SSH/SFTP、工作区注册和双会话隔离；增加弱网、失败和取消场景。单元/组件测试与独立浏览器夹具只能证明对应层行为；最终仍需在目标 DSH Web 版本内完成宿主集成验证。

## UI 与交互细节的共同验收标准

- 信息层次：一个界面只有一个突出主操作；主机和目录同时可辨；高级配置按需展开。避免向普通用户暴露 currentId、镜像实现和后端参数。
- 视觉：采用宿主主题 token；统一字号、间距、边框、按钮与图标；同时检查浅色/深色、长主机名、长路径、中文/英文和窄窗口。
- 稳定性：补全、加载和错误提示不遮住主操作；列表更新不抢焦点；慢请求不覆盖后输入的内容；已选路径可查看完整值。
- 键盘：主机搜索、目录建议、确认和返回可连续完成；输入法确认不触发提交；快捷键不重复执行；关闭弹层后焦点返回触发入口。
- 状态：分别呈现初次加载、无数据、无匹配、进行中、成功、失败、断线与恢复。不能把请求失败展示为“没有主机/文件”。
- 可恢复：失败保留表单和路径；错误出现在对应操作旁；取消不产生后续打开行为；删除、覆盖、同步冲突需要清楚说明对象和后果。
- 性能：本地搜索和选择给出即时反馈；远端请求去抖、去重并丢弃过期响应。以请求日志和慢网场景验证，不用动画掩盖等待。

### 本次验证方法

- 在现有 checkout 运行语法检查、`node check.mjs`、完整 `npm test` 与 CI 覆盖率门禁。
- 在仓库外安装并启动隔离的 `@deepseek-ai/dsh@0.2.0-rc.2` Web 宿主，以两个本地 ssh2 服务验证真实协议和原生工作区交接。
- Chromium 实测项目搜索、键盘打开、只发送一次镜像请求、原生注册、再次打开、切换主机、目录补全、浅色/深色和 390px 窄窗口；不调用模型 API。
- 仓库测试脚手架补全了清理事件监听的 document 接口，以测试同一选择器关闭/重新打开时的真实 effect 生命周期。

### 仍需区分的边界

- 真实宿主的主要打开流程已经验证；公网/企业 SSH、真实认证交互、长时间断网与大目录压力尚需对应实机验收。当前中断恢复是保留界面并手动重试，不进行后台无限重连。
- 草稿暂存属于当前页面进程内存，支持组件重新挂载；浏览器刷新或进程退出会丢失，尚未实现加密持久化草稿。
- 同步状态记录本次进程实际操作，不代表两端持续相等。只有启用现有 autoPush 时，才能由 watcher 观测待推送改动；不扫描全部本地文件来推测“已同步”。
- 取消会关闭本次打开独享的目录探测连接，不关闭其他会话共享池。请求进入本地工作区提交后仍存在响应丢失的不确定窗口，界面要求先检查工作区列表，不自动重放；不宣称分布式事务式撤销。
- 文件栏新增的终端快捷入口使用宿主 `webTerminals.launchShells` 和 `sidebarRight.openTab` 契约，显式选择 `remote ssh`，不修改用户默认 shell。未涉及宿主语言服务、扩展、Git 执行位置及远端服务架构。
- 验收宿主与测试主机均在隔离目录中运行，不修改正式用户 profile。


### 实际会话工作区的持续操作优化

- 文件树改为紧凑工具栏和统一行高，补充选中态、明确的展开箭头、已加载文件筛选、全部折叠、远程终端入口。展开目录、选中文件和滚动位置按会话保留。
- 文件默认以宿主标签页打开，避免默认分栏把编辑区和终端压窄；用户仍可使用宿主分屏和全屏。返回文件树恢复目录上下文。
- 文件视图统一文件名、路径、工具栏和底部状态栏，支持复制内容/路径、自动换行、文件内查找、匹配计数与跳转、Markdown 预览/源码切换、行号和宿主语法高亮。保留最近 64 个会话文件的页面内预览与阅读位置；缓存立即展示，同时重新读取远端。
- 编辑支持 Tab/Shift+Tab 缩进、Ctrl/Cmd+S、光标行列状态，保留 IME、草稿、保存互斥、远端 mtime 冲突和截断文件保护。缓存刷新期间禁止以旧基线开始编辑。
- 远程终端入口显式选择注册的 `remote ssh`，异步发现 shell 期间若会话切换则不打开；缺少宿主服务显示原位错误。继续使用宿主原生 PTY、输入、滚动和缩放。启动上下文压缩为 SSH 目标与目录，元数据过滤终端控制字符；在镜像子目录启动时映射到相同远程子目录。

验证使用隔离的真实 DSH Web 0.2.0-rc.2、Chromium、本地 SSH/SFTP 测试服务，并将 SSH 交互通道接入真实 Bash PTY。浏览器完成展开目录、打开/查找/编辑/保存、返回后选中恢复、筛选、折叠、Markdown 双向切换、远程终端输入与命令输出、`pwd` 目录和 PTY resize 检查。终端断言检查独立输出行，避免把命令回显或启动目录提示误当成成功。SFTP 使用测试文件系统；不代表公网实机和长时间会话压力已经验收。


### Agent 任务与结果呈现

Agent 侧验收使用完整 AgentLoop、工具分发、会话日志与真实 SSH/SFTP 磁盘工作区：编译失败、读取诊断、修复源码、重新编译、运行程序。另验证执行中停止及同会话后续任务；本地镜像哨兵保证操作发生在远端目录。

通过正式 SessionController 和宿主 preset 创建任务，在真实浏览器中检查最终回复、命令退出码、GCC 诊断与对应远端源码行。脚本模型负责可重复的状态回归；真实 DeepSeek 模型负责自主任务验收，两者单独记录。PTC 使用实际文件沙箱，不通过关闭沙箱来获得绿灯。

远程工具使用专用结果卡片，命令事实写入持久化展示元数据；PTC 子调用文本同样带明确退出码。保留真实 shell 退出状态，额外突出编译错误，覆盖“编译失败但后续 echo 返回 0”的真实模型行为。诊断可跳转文件对应行，再次打开同一文件会重新校验 Agent 修改；已有脏草稿仍保留并走冲突检查。

最终版本与各项验收证据统一记录在 [1.0 发布验收](../release/1.0.0.md)，避免在设计文档保留互相矛盾的中间测试数量。公网主机没有计入通过；Desktop 原生应用和 Kerberos 环境仍按明确范围说明。


### 主机设置的最终职责

主机设置不负责选目录或进入工作区，也不展示全局“当前远程机”。打开页面自动探测各主机并展示 SSH 建连与命令探测总耗时，探测不会采用主机或切换任何会话。失败原因默认折叠，刷新可重测，注册表轮询不重复连接；队列并发上限为三，页面关闭后丢弃晚到结果。目录只在侧栏新建远程工作区流程选择，每个工作区独立绑定主机。

设置页分为主机、连接工具和插件偏好，使用独立的远程终端图标。列表状态列、编辑表单、复选项与辅助说明统一对齐；编辑草稿在当前页面内存保留，取消需要确认放弃修改。真实浏览器验收覆盖桌面、手机、深色、键盘导航、菜单、测试与保存；具体脚本见 `scripts/manual/settings-web-e2e.mjs`。
