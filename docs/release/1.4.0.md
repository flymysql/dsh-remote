# 1.4.0 — 工作区文件直读远端与连接修复

- **镜像会话的核心文件表面直读远端（#194）**：宿主 `workspaceFiles` 服务（文件预览、字节窗口、工作区列表）此前按会话 cwd——远程会话即本地镜像——解析路径，远端在插件外被改动时读到的是陈旧镜像内容。现在这些调用在命中镜像绑定时通过 SFTP 直达远端：路径映射与 `rw_*` 工具同款（相对路径拼镜像 remotePath、镜像内本地路径映射到同一远端文件、其余绝对路径按远端执行世界解释），分页/字节窗/列表的容量上限对齐核心部署配置，错误沿用 `workspace-file/*` 码。`changes` 变更流仍观察本地镜像——SFTP 没有 inotify，插件自身的写照常触发失效，仅远端外部改动不触发。配置 `workspaceFilesRemote: false` 可整体退回镜像行为。
- **远程 Markdown 插图渲染（#183）**：远程会话的 Markdown 预览中，相对路径插图（png/svg 等）此前只显示替代文字；现在从远程工作区实际读取并渲染。
- **OpenSSH 建连超时重试（#188）**：系统 OpenSSH 后端在 ConnectTimeout 到期时重试一次。实测约 6% 的新建连接因瞬时超时失败、耗时 15.5 秒，单次重试即可吸收；认证失败等非瞬态错误不重试。
- **远程工作区选择器恢复（#180）**：explorer 的工作区选择器重新可用，不再调用已失败的 registry local，镜像会话的项目选择不再空白。
- **工程治理（#192）**：e2e 脚本端口改为向内核申请空闲端口并加 CI 静态守卫，消除 agent-acceptance 偶发 `EADDRINUSE`。

## 安装

```sh
dsh plugin --profile web add dsh-remote@1.4.0
```

重启 DSH Web 并刷新页面。SSH 主机、镜像与工作区记录无需重建。文件预览改为直读远端后，远端不可达时预览将显式报错（而不是展示陈旧镜像）；需要旧行为可设 `workspaceFilesRemote: false`。

## 验证与范围

#184 / #189 / #190 / #195 四个修复 PR 的 Linux、macOS、Windows 与六组 Agent 验收（0.2.0-rc.2 / 0.2.1-rc.5 / 0.2.2-rc.1 × native / PTC）全部通过；#195 另有 15 条单元测试（远端服务、分页与容量语义、路径映射、错误码、非镜像回退、中止与还原语义，行覆盖 96%）。合并后 main 的 CI 与 Agent 验收均为绿。文件直读远端复用既有 SSH/SFTP 连接池与镜像绑定规则（meta 缺失即拒绝、不猜主机、不碰活动机器）；`changes` 的远端外部失效与 better-sidebar 文件面板的远端数据源仍待上游提供词汇（omdsh-dev/DSH-better-sidebar#1247）。

## English

Mirror sessions now serve the core `workspaceFiles` surfaces (previews, byte windows, workspace listings) from the remote origin over SFTP instead of the stale local mirror, with the core caps and error codes; `workspaceFilesRemote: false` restores mirror behavior, and `changes` still watches the local mirror. Relative Markdown figures in remote sessions render from the remote workspace. The system-OpenSSH backend retries a transient connect timeout once. The remote-workspace picker is restored. Restart DSH Web and refresh after installation.
