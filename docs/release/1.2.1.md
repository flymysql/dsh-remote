# 1.2.1 升级恢复与兼容性验收

本版集中修复旧更新器写坏安装、会话工作区识别及依赖闭包问题，重点是“升级过程不 brick、升级后插件能加载、旧会话仍可工作”。

## 主要变化

- 旧 `lib/index.js` 与当前 `lib/boot.js` 共用 self-heal guard，真实主体位于 `lib/main.js`；旧 0.8.x 首次升级到本版也能在外层捕获缺失文件并修复。不同 query 继续产生独立模块实例。
- `applyUpdate` 按 tarball manifest 进行写前备份、落盘后逐字节校验、原子 marker 和失败逆序回滚。回滚失败保留 backup，不能把半更新树当作成功。
- 外部修复命令为 `node <profile>/node_modules/dsh-remote/lib/self-heal.js`。默认读取磁盘版本，可显式传 `--version`、`--dir`、`--tarball`；本地 tarball 不访问 registry。修复前停止 DSH，完成后重启。
- alias-native 连接摘要使用 resolved 身份；当前 DSH session log 的格式段与压缩后缀均可识别；本地工作区在 registry 刷新期间不降级，失败时不错误归类为本地。
- vendored structuredPatch 使用 diff 9.0.0 的完整 ESM 依赖闭包，保留 BSD-3-Clause 许可；不新增运行期外部依赖。

## 兼容性边界

- 支持 Node 22/24；DSH 0.2.0-rc.2 / 0.2.1-rc.5 / 0.2.2-rc.1 的 native 与 PTC 验收分别记录。0.2.0 PTC 宿主仍不保存子调用展示元数据，不伪造已应用 diff。
- 旧 `lib/index.js?case=...` 与 `lib/boot.js?case=...` 仍按 query 隔离模块状态，避免共享机器与连接池。
- 已被旧版本写坏的安装如果 `self-heal.js` 或 `update.js` 自身也缺失/损坏，不能靠包内脚本恢复，应使用 `dsh plugin --profile <profile> add dsh-remote@<fixed-version>` 重装。
- 事务不保证进程 kill、断电或多进程同时写入时的目录级原子交换；外部修复应先停止 DSH，避免 auto-update/HMR 并发写同一棵树。
