# 1.3.0 安全加固、主机感知转发与宿主控件统一

本版把两处安全缺口补上（工具面写本机无围栏、自更新缺完整性根），修掉 junction/symlink 下远程工具全拒的阻断问题，并让端口转发真正按主机隔离。

## 主要变化

### 安全

- `rw_download` 是全部 `rw_*` 中唯一写本机却不经 `requireRemoteSandbox` 的工具：read-only 会话也能把远端文件写到本机任意路径（例如 `~/.ssh/authorized_keys`），且没有符号链接防护与审计。现在与 HTTP 下载路由对齐——read-only 拒绝落盘、workspace-write 把远程源约束在工作区、目的地一律限制在会话镜像内、落盘前拒绝符号链接、补写审计。顺带修掉默认路径的字符串前缀切片错位（`/data/proj` vs `/data/proj2`）与远端名含反斜杠时在 Windows 宿主逃出镜像。
- `machines.json` 在默认 `credentialBackend: plain` 下携带明文密码与私钥 passphrase，此前权限走 umask（实测 0644）。现在每次保存后收紧到 0600，既有松权限一并收紧；Windows 上目录已私有，按既有惯例忽略错误。
- 自更新此前对下载字节只做「tarball 自述版本号」校验，攻击者控制的响应可任意回显，完整性根只剩 TLS。现在下载前取 npm 的 `dist.integrity`，解包前做 sha512/sha256 SRI 比对；元数据缺失时 fail-closed，非法/未知版本在 metadata 阶段即失败、不下载任何字节。离线 `--tarball` 路径保持零网络请求。

### 行为变更

- `rw_download` 的显式 `localPath` 必须位于工作区镜像内；没有远程工作区时不再接受任意绝对路径。这是恢复该工具声明的语义（HTTP 路由一直如此），失败为显式报错而非静默写错位置。依赖旧行为把文件写到镜像之外的脚本需要改为先下载到镜像、再自行移动。

### 修复

- `~/.dsh` 是 NTFS Junction 或符号链接时（Windows 上把数据目录放到其他盘的常见做法），会话 cwd 与注册根拼写不同，`resolveMirror()` 的纯字符串前缀比较判定「不属于任何镜像」，会话被当作 LOCAL，`rw_*` 全部拒绝。现在同时扫描字面与真实路径两种拼写，Windows 上大小写不敏感，返回的 `mirrorDir` 按会话 cwd 的拼写重新表达；没有 meta 的目录依旧绝不绑定。
- 编辑**当前**机器后只写注册表、不重指连接池，导致设置页显示新地址而「启动」仍连旧地址（`ssh: connect to host <old>: Host is down`）。现在保存当前机器会立即 `applyActiveMachine()`，失败以 `poolWarning` 回传；保存非当前机器不抢占活动连接。
- 普通本地工作区不再被本插件的资源管理器接管，保留宿主自带的 reveal / 用其他应用打开 / 上传 / 新建 / 归档等动作；远程镜像会话继续使用插件 explorer。

### 功能

- 端口转发添加时可选「主机」，未连接的主机也能先存下转发；已有转发可编辑方向、端口、目标与所属主机，运行中的先停止再按新配置重启（服务端对运行中改 bind 返回 409，仍允许切换「自动重连」）。
- 直接写在 `~/.ssh/config` 里的 Host 与已保存机器共用同一个「…」菜单，可直接「编辑」保存成机器并填写登录密码，保存前后入口形状不再变化。
- 设置与远程搜索面板改用宿主 Menu / Select / Disclosure / Checkbox / 图标 primitives，移除自绘下拉与 `▾` 折叠，样式变量对齐宿主；宿主未提供对应组件时回退原生控件。
- 菜单锚定同时传 `anchorRef`/`anchorPoint`（DSH 0.2.2 起的 CSS 锚点）与 `getAnchorRect`（更早宿主）：旧宿主忽略新属性并用 rect，新宿主忽略 rect 用 ref/point，因此不会出现「菜单贴到页面角落」。

## 兼容性边界

- 支持 Node 22/24；DSH 0.2.0-rc.2 / 0.2.1-rc.5 / 0.2.2-rc.1 的 native 与 PTC 验收分别记录。宿主未提供 UI primitives 时，设置与搜索面板使用原生控件回退，功能不缺失但样式与宿主不完全一致。
- 从 1.2.1 及更早版本升级时，执行安装的是**旧版更新器**（1.2.1 不含 integrity 校验）；`dist.integrity` 从本版起对后续升级生效。因此本版必须能由旧更新器正确安装——升级矩阵即验证这一点。
- `rw_download` 的收紧属有意行为变更，见上；`machines.json` 权限收紧在 Windows 上不改变 ACL（目录已私有）。
