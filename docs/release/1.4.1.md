# 1.4.1 — Windows OpenSSH 探测修复与 IDE 底板加固

- **Windows cmd.exe 默认 shell 的主机可连接（#197/#198）**：系统 OpenSSH 后端的连接探针此前发送裸 `true`——cmd.exe 没有这个命令，健康主机在设置页被误报「不可用」，且 sshd 的 cmd.exe 错误文本是 GBK、按 UTF-8 解码后显示为乱码。探针改为 `echo ok`，cmd.exe / PowerShell / POSIX shell 通用。

- **平台探测链修复（#199/#201）**：Windows OpenSSH 会把客户端命令重包成 `cmd.exe /c "…"`，裸的单 token 探针 `cmd /c ver` 到达内层 cmd 时多出一个游离引号（`'ver"' 不是内部或外部命令`），探针改为引号形式 `cmd /c "ver"`——Windows Server 2019 等保持默认 cmd.exe 默认 shell 的主机不再被误判为 posix（此前工作区选择器去 `sftp.readdir('/')`，驱动器列表完全出不来）。

- **Git Bash 默认 shell 支持（#197/#201）**：把 Git Bash 设为 sshd `DefaultShell`（`DefaultShellCommandOption -c`）的主机，此前 `cmd /c ver` 也会成功，随后选中的 Windows 路径 bash 包装是 POSIX 默认 shell 无法执行的（引号反斜杠路径到达时已损坏）。现在 `uname -s` + `echo $0` 先行识别 POSIX 默认 shell，并以 POSIX 形式定位 bash（`command -v bash` → `/usr/bin/bash`）；`uname` 回答 MINGW 的歧义情形（cmd.exe 默认 shell + Git usr/bin 在 PATH 上）由 `echo $0` 区分。两个后端的探测器统一为 `lib/detect-platform.js`（此前是两份已漂移的拷贝），POSIX 主机的探测开销从两次降为一次。

- **IDE 模式底板加固（#200/#202）**：壁纸/玻璃主题（如 dsh-plugin-wallpaper-engine）会把 `--dsw-alias-bg-base`（玻璃档连 `--dsw-specific-sidebar-fill`）置为 transparent，而 IDE 壳的四处表面此前只用该 token 当唯一底板——整个壳变透明：宿主会话列表穿出文件树列（两套文字交错重叠），欢迎页与聊天正文直接压在壁纸照片上。现在每个表面把原 token 作为顶层、叠在 `--dsw-alias-bg-layer-1` 实底之上：原生主题像素级不变，alpha 主题落到实底。

## 安装

```sh
dsh plugin --profile web add dsh-remote@1.4.1
```

重启 DSH Web 并刷新页面。SSH 主机、镜像与工作区记录无需重建；无配置变更。

## 验证与范围

#198 / #201 / #202 三个修复 PR 的 Linux、macOS、Windows 与六组 Agent 验收（0.2.0-rc.2 / 0.2.1-rc.5 / 0.2.2-rc.1 × native / PTC）全部通过；#201 另有 14 条双后端单元测试（引号探针、POSIX 默认 shell、MINGW 歧义消解、POSIX 短路、native 配置、共享实现守卫），#202 有 IDE 表面底板回归测试。合并后 main 的 CI 与 Agent 验收均为绿。平台探测与 IDE 底板改动不影响连接、镜像与既有工作区语义；`workspaceFilesRemote` 等既有配置项不受影响。
