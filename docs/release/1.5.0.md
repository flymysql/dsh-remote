# 1.5.0 — 链路自愈、浏览器下载与性能修复

- **Web 界面隧道路由自愈（#204）**：跨网段链路抖动 30–60 秒后，本地监听（如 `127.0.0.1:3088`）仍接受连接但每个连接被 RST，远端 dsh web 进程健在、端口仍在 LISTEN——此前只能手动断开重连（且端口被空壳监听占死）。现在连接丢失后自驱重连循环（`pool.connect()` 带退避 1s→30s 封顶；池内 memoize 并发共享一次拨号），成功即沿既有 onReady 链重挂客户端并重解析远端端口（远端进程没挺过去则自动重启它）。本地端口全程保持绑定，浏览器 URL 恢复后直接可用。

- **下载到运行浏览器的那台机器（#209）**：新增 `GET /dsh-remote/download`——会话作用域绑定、`maxFileBytes` 上限、按 1 MiB 分块背压流式（宿主内存恒定、无临时文件）、RFC 6266/5987 头保证中文文件名不丢。文件树行尾下载图标、右键菜单「下载到本机」、文件标签页工具栏按钮三个入口，把字节交给浏览器自己的下载管理器（进度/取消/断点由浏览器负责）。DSH 宿主与浏览器不同机时不再需要 scp 回传或 cat 复制粘贴。「下载到本地镜像」保持原样；本地工作区下载仍受会话根目录围栏约束。

- **高 RTT 链路每条命令提速约 6 倍（#211）**：两个叠加缺陷修复。① `~/.ssh/config` 别名机器采纳时不再无条件钉在 openssh 后端（每条命令 spawn 一个 `ssh`、重付 TCP+SSH 握手）——Host 块携带 `IdentityFile` 且无 `ProxyJump` 时改用 native 长连接（文件仍是连接时的唯一事实来源）；② native 池在连接 ready 后调用 `setNoDelay(true)`（ssh2 拆包写出叠加延迟 ACK，72ms WireGuard 链路实测 `echo ok` 856ms→146ms、设置页探测 2596ms→826ms）。旧版本保存的别名机器需从 ssh-config 列表重新导入才能切到 native。

- **堡垒机终端可用（#212）**：JumpServer 类网关只给不带命令的登录分配远端 PTY——带命令会话（即使 `-tt`）无行纪律：回车不生效、zsh ZLE 不启动；`script -q -c` 包装后字符重复、`stty size` 恒 0 0。新增每机器选项「终端用纯登录」（设置 → 高级）：生成的终端 launcher 发 `ssh -tt <target>` 不带命令，网关交给登录一个真 PTY（行编辑与窗口缩放正常），代价是放弃自动 cd 到工作区。直连普通 sshd 的机器保持原行为。

- **per-machine `shell` 配置真正生效（#206）**：该字段此前在 schema 声明、两个后端的探测都读取，但 `applyMachine()` 丢弃、`setTarget()` 签名里没有、保存机器时还会被重建抹掉——手工编辑 machines.json 也无效。现在全链路生效：设置页高级区新增「远端 Shell」输入框，`rw_connect` 接受 `shell` 参数，机器切换时 shell 变化会重置缓存的平台探测。

- **下载可见性（#207）**：文件树的「下载到本地镜像」此前丢弃响应（零反馈，用户以为下载失败）。现在文件树与文件标签页都显示落地路径 + 「在文件夹中显示」按钮（新增 `revealLocal` 路由，`openLocalPath 'reveal'` 围栏限定在插件自己的镜像树内，拒绝任意本地路径）。

- **rw_pick_workspace 语义澄清（#205）**：描述与成功文案明确写出「不切换当前会话的工作目录」——已绑定会话的相对路径、`rw_exec` 的 cwd 与 `rw_sync` 仍解析到原工作区，直至在新镜像里打开会话；pick 与当前绑定不同时成功文案显式警示，并给出 git worktree 并行开发的正确姿势（一个 worktree 一次 pick、每个镜像一个会话）。

## 安装

```sh
dsh plugin --profile web add dsh-remote@1.5.0
```

重启 DSH Web 并刷新页面。SSH 主机、镜像与工作区记录无需重建。新增能力均为可选：浏览器下载与「在文件夹中显示」开箱即用；「终端用纯登录」与 per-machine shell 按机器在设置 → 高级中开启。
